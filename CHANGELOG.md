# Changelog

Newest first. Older changes are in the git log.

## 2026-11-27 — iPhone page: the session panel is a chat room in the chat theme
- With the chat theme on (Light / Dark / Match System), the open session's panel shows the session as a chat room, like the desktop app: your prompts on the right in yellow bubbles, replies on the left with the session's picture and name (markdown rendered, long ones folded with See more), tool calls as small grey lines (a long run folded to "+ N more tool calls"), times, day dividers, pictures (tap for full size) and a "…" bubble while the session works. It reads the session's transcript (/api/chat, forwarded for a session on the other Mac) every 2 s while it works and every 6 s when idle, never while the page is hidden or on Grid; only changed rows are redrawn and it follows the newest message unless you scrolled up (↓ jumps back). New file phone/phone-room.js.
- A **Chat / Terminal** switch in the session header goes back to the live terminal (Chat / Status for a session without a terminal here); the choice is kept on the phone. The Default theme shows the terminal as before. The key row and the input bar keep working in the room; a sent message shows as a pending bubble (read mark "1") until the transcript has it, matched ignoring spacing, file paths and [Image #n].
- Text in the room can be long-pressed for Select / Select All / Copy (also the terminal's text rows); buttons and keys stay unselectable.
- Attaching with + no longer puts the uploaded file's path into the text box: attachments wait as chips above the input (a picture as its thumbnail, × removes it) and their paths are added only when sent; the pending bubble shows the picture. Same for the session sheet and the status panel.
- Narrow phones: the Display and switch buttons in the header show the label over the state (each cut with …, never mid-word, the last-run time hidden), so the title keeps its 90 px and nothing runs off an iPhone 15's screen. The session header's picture shows its initial again (a rule hiding the name also hid it).

## 2026-11-27 — Code map, all projects: a Detail view
- **Simple / Detail** in the all-projects header. **Detail** draws every project's real items and links instead of one hub and its biggest areas: small dots coloured by area (a pastel palette per project), hair-thin curved links, each project a dense cluster around its hub (picture and name, small), loose areas floating as islands, and the links between projects (folder, imports, same names, messages, lineage) drawn faintly between the clusters. Big projects are sampled: half their best-linked items and half spread over their areas, at most 1,500 per project and about 9,000 items / 15,000 links in all (both Macs share the budget), so the header says "showing N of M items". Hover an item for its name, file, area and project; click it to light up its neighbours; double-click a cluster to open that project's own map. Search dims everything that doesn't match. The layout runs once in a Web Worker and then stays still; drawing is batched per colour and only what is in view, so panning stays well under a frame (about 1 ms per redraw with 8,300 items). Its data is a separate call (the Simple view stays light), cached per graph.json; the other Mac's half comes from GET /api/codemap-hub?detail=1. The choice is remembered; light and dark themes both have their own look.
- Simple view: labels no longer overlap. A session's name under its picture and the project's name under the hub (two sessions on one folder, say) now go below, above or beside their dot, wherever there is room; area names that fit nowhere are left out until you zoom in.

## 2026-11-27 — At most 6 detached chat windows

Each Mac now serves its half (GET /api/codemap-hub, its own sessions and maps) and the window merges the other Mac's in: its projects with their areas, a folder both Macs work in as one hub, and folder-inside links across the two Macs.

## 2026-11-27 — Detached chat windows load their own data and report errors

The window now asks for the snapshot itself once it has loaded (and again 1.5 s later) instead of relying only on the push, shows any error in the window, and logs errors, hangs and crashes to chatwin.log in the app's data folder; a crashed page reloads.

## 2026-11-27 — Code map: all projects in one picture
- **Code map** is now a view of its own: the new graph icon in the chat theme's left rail, or **View ▸ Code Map (All Projects)** (⌘⇧M) in any theme. Its home page, **All projects**, draws every session's project as a hub (its picture or initial and name) with its code areas (Graphify communities, sized by how many items they hold) hanging off it. Hubs are linked where they really connect: a project folder inside another (with how many files the outer map shares), one project importing a module that is another's file, the same distinct code file names, messages between their sessions in the last 24 h, and sessions of the same handed-off lineage. Several sessions on one folder share its hub. Hover a link for what it is; click a hub for its details; double-click it, or click a session in the side list, to open that session's own map in the same window with **‹ All projects** to come back. Only maps that already exist are read (never a build); a project without one is a grey dashed hub with **Build map**. It follows Mesh's theme (light / dark) and sets the per-project map's own Light / Dark to match. Summaries are cached per graph.json, so twenty projects with thousands of items each stay smooth.

## 2026-11-27 — A sent message no longer shows twice in a chat room
- The "sending" bubble stays until the session's transcript has the message, matched by exact text. The terminal sometimes changes spacing (a double space came back single) or adds the attached files' paths, so the match failed and the message showed twice for a minute. The match now ignores spacing, file paths and [Image #n] tags.

## 2026-11-27 — Dragging a divider no longer lags
- Dragging the divider between panels (the Terminals panel, the sidebar or the dock split) refitted every terminal on every mouse move: each pixel reflowed the whole scrollback and resized the tmux pane, so Claude Code redrew non-stop. Terminals now keep their size while you drag and refit once when you let go; the panel size follows the pointer at most once per frame.

## 2026-11-26

- **Orbit view: a session's picture pops up over its bubble.** Rest the pointer on a bubble (about 0.6 s without moving) and the session's picture (GIFs animated, else its initial) pops up above it with its name, follows the bubble, and fades out when the pointer moves off, leaves the view or clicks. Resting on the mother star shows the sun session's picture. Pure DOM (renderer/orbit-avatar.js); nothing runs while the pointer is outside the orbit view.
- **Session pictures.** Click a session's avatar (a Simple-board card, a chat-list row or a room header, detached rooms too) to pick any picture or GIF from the pictures folder (`avatars` in mesh.local.json). Each is cropped to a centred square at 256 and 512 px (a wide GIF loses its sides and corner marks) and GIFs stay animated. The pick belongs to the session's NAME, so handoffs, refreshes and new generations keep it; it merges between the two Macs by name (last write wins) and shows on the other Mac within seconds. Pictures show on the board cards, chat list, Terminals tabs, room headers, the Live panel header and the iPhone page; sessions without one keep the initial letter. The picker has **Letter**, **Sync now** (runs the folder's sync command), **Show folder** and **Open in Drive**.
- **Sends clear the paste-bug leftovers by themselves.** A session's input box that holds only what the old room-paste bug left there ("[Image #13]" tokens, "Image pasted as …png", paths in Mesh's paste folder) is cleared with Ctrl+U before the send, so the send goes through. A box with anything a person typed is still never touched.
- **A send from the other Mac says at once when the session's input box isn't empty.** Mesh never types into a half-typed message; for a person's send from the other Mac it used to wait up to 2 minutes and the room showed only "Not sent: timeout". It now fails at once with "its input box already has unsent text (open its terminal view and clear it)". Relays and scripts still wait up to 2 minutes as before.
- **Fix: a restart during an install rolled the update back.** The restart helper waited for the exact version it expected; when the MacBook's auto-update installed a newer one during a manual restart, the newer one came up, did not match, and was replaced by the previous copy (the Mac stayed on the old version however often you restarted). The helper now counts any version that starts as up and rolls back only when nothing starts.
- **Chat theme: light and dark, the whole window, and rooms in windows of their own.** **View ▸ Theme** (and the star menu) now offers Default, the chat theme Light, Dark and Match System (follows macOS); every window follows a change. The theme now covers the whole main window: the header (grey pills, the Mesh / Split / Grid switch as pill filters, a yellow **+ New**), the dock's panel tabs, the Terminals tabs (one pill per session with avatar and unread badge), the Simple board (cards with avatar, bold name, grey details, unread badge), Details, menus and toasts; the Sessions panel gets the messenger's left icon rail. Dark follows the messenger's macOS dark mode (#1E1E1E list, #2A2A2A rail, #1C1C1C room, dark-grey replies, yellow own bubbles and read counts). Unread badges are red-orange (#FF5A36). A room or the chat list can be taken out into a window of its own: drag its tab out of the window, double-click a session in the list, or the pop-out button; several rooms can be open at once. Closing the window (or its dock-back button) puts it back; each window keeps its size and place per session (`chat-windows.json`). Detached windows use the same chat code (transcript, send, attach, paste, the other Mac) and get snapshots only while visible, so nothing polls more than a docked room did. Your sent message shows a yellow **1** until the session has it. Selected text in rooms is now clearly visible (blue, white on blue in your yellow bubbles); before, the selection was almost invisible on the light theme. The Default theme is unchanged.
- **Fix: ⌘V in a chat room went into the terminal underneath.** The terminal's own paste catcher took ⌘V first, so pasted pictures and files never showed as chips; they were typed into the session's hidden input box instead, and that leftover text then held every later send ("Not sent: timeout"). A paste in the room's input box is now the room's own: Finder-copied files and screenshots become chips (a copied file no longer pastes as its name), text pastes as text. Attachments sent to a session on the other Mac are uploaded there first, and a send to the other Mac waits up to 2 minutes (its half-typed-box guard) instead of timing out after 6 s.
- **Chat theme: a messenger look, with pictures and files.** The chat theme is now a light messenger look and can be picked in **View ▸ Theme** (Default / the theme's `chatThemeName`), kept in sync with the mother star's menu. Rooms have a blue-grey background, yellow bubbles for your prompts and white ones with avatar and name for replies, a tail on the first bubble of a run, the time (오후 3:12) beside the last bubble of each minute and date pills; the chat list is white with rounded-square avatars, bold names, grey previews, times and red unread badges. Pictures in a prompt (pasted screenshots kept in the transcript, or a picture file you attached) show as pictures: no bubble, rounded corners, up to 240 px wide with their shape kept, several as a 2-column grid; click opens a full-size viewer (← →, Esc closes). The input bar shows attachments (+, drop, paste) as chips you can remove before sending, and its **전송** button turns yellow when there is something to send. Tool calls stay one grey line each, nothing polls more than before, and the default theme is unchanged.

## 2026-11-22

- **Top-bar switches with a last-success time.** New mode-switch options: `"place": "top"` shows the switch as a button next to the screen-share button (and in the phone's top row) instead of a pill in the switch row; `"defaultOn": true` makes a missing file count as ON (only `"enabled": false` is OFF); `"lastFile"` (a JSON `{ "at" }`) adds the tool's last success, e.g. "Autologin ON · 23:03"; `"confirm": "off"` asks only before turning it off (`"none"` never asks).
- **Server display control.** With `"display": { "host": "<the always-on Mac>", "label": "Mini display" }` in mesh.local.json, the other Mac's screen-share button in the top bar shows that Mac's display state as a dot (green on, hollow off, amber when OFF isn't allowed), read live (CoreGraphics) every 15 s. Right-click the button (on the phone: the Display ON/OFF button in the top row) to turn the display OFF (`pmset displaysleepnow`, only the display sleeps) or ON (`caffeinate -u -t 2`). OFF is refused while system sleep is enabled or the Mac would lock after its display turns off, and the menu says why; Mesh never changes those settings. OFF writes `~/.mesh/display-off` so keep-awake helpers can skip their nudges until ON removes it. Every ON/OFF request is logged with where it came from in `display.log` next to the flag. Note: a Screen Sharing session to that Mac turns its display on (macOS does this).
- **Vacation mode for a mode switch.** A switch configured with `"vacation": true` gets a Vacation mode block in its right-click menu: start and end dates, daily hours, the admin who answers instead of you, how often the tool runs (default 3 min) and an optional faster window (default 1 min, 09:00–10:00). Saving checks the values, keeps the admin's ids that the tool filled in, and runs the tool once right away. While it's active a "Vacation · 3m" tag shows next to the pill, the countdown uses the vacation interval, and the pill doesn't say "Paused" outside the normal schedule.
- **No refresh loop when a session's rulebook alone fills its context.** Session refresh now remembers how big each refreshed session starts. When a session passes its context cap but is still within half a cap of that start, another refresh can't bring it down (the new session would read the same files and land in the same place), so it alerts once a day to trim the handoff's rulebook list or raise that session's cap, instead of refreshing every few hours. A session that started at 296K hit the 300K cap again three hours after its refresh.

## 2026-11-21

- **The idle pause now really stops the green "working" glow.** The pulse is synced from script, which stopped the CSS pause from reaching it, so the window kept recalculating styles about 145 times a second while nobody was there. Now the pulse pauses too, and the renderer does about 98% less work while paused. A page reloaded while nobody is there (a hot update, crash recovery) now starts paused too; before, it ran at full work until the next touch.
- **No more typing into a sub-agent by mistake.** While you look at one of a session's sub-agents, Claude Code's input box says "Message @<agent>…" and anything typed goes to that agent. Session refresh now skips such a session ("its input box is on sub-agent @…") instead of sending its handoff request there and waiting 30 minutes for an answer that never comes, and sends from the phone, relays and scripts are refused with the same reason instead of reaching the wrong conversation.
- **Rests when nobody is at the Mac.** After 10 minutes with no keyboard or mouse input (and no Screen Sharing viewer), the window is treated like a hidden one: the mesh stops drawing, terminals take their output in 10-second batches and CSS animations pause. The first touch brings everything back within about 2 seconds. A MacBook left on with the display awake for 5 hours had been using about 19% CPU this way. `MESH_IDLE_AWAY=<seconds>` changes the wait.

- **Terminal tabs show the session name.** The tag next to a tab said "Mac mini · command session" and squeezed the name to "GCX …". It now says only the Mac (plus Hermes / script / helper when it isn't a normal session; the full text is in the tooltip), the name keeps at least 9 characters and the tag gives way first, and tabs may be 300 px wide (was 260).
- **Version 1.2.1: lighter while open.** The iPhone page no longer loads the mesh engine it stopped drawing on 11-15 (13 scripts and the three.js 3-D models): it now loads 7 scripts instead of 21, through a small stand-in (`phone/phone-viz.js`). On the Mac: the idle screen saver is off unless you tick it in View ▸ Mesh (its once-a-second idle poll stops too); the Live panel stops polling its job and its Chrome screencast while the panel is closed or the window is hidden; the All sessions list reloads every 60 s and not while hidden (was 20 s); countdowns skip hidden windows; the folder-stall check runs every 60 s (a slow call still flags a folder at once) and the memory popover's process list every 2 min.
- **Folder mirror stays small.** The iCloud viewing copy (`folderMirror`) now skips media work products (frames, upscales, renders, masters, video and audio, caches), caps files at 10 MB and each folder at 1 GB after filters (bigger folders aren't mirrored), and mirrors exactly with `--delete`, so pruned or skipped files leave iCloud too. Edits made in the copy are lost on the next pass. Before this, one project's upscale frames filled 12 GB of iCloud Drive and stayed there after the originals were pruned.
- **Sessions that run a skill get its folder.** A session started in the home folder that works through a hidden link (`~/.claude/skills/<name>` → the real skills folder) had no project folder, so no folder button and no Code map. Paths through a hidden link now count as the real folder they point to. Checked on 15 live sessions: three that had no folder now get their skill folder; every other session's folder is unchanged.
